## 2. DNS Records

Replace the Railway targets with the exact CNAME targets shown in each Railway service's Domains panel.

| Type | Name | Content | Proxy | Notes |
| --- | --- | --- | --- | --- |
| CNAME | `@` | `<RAILWAY_WEB_CNAME_TARGET>` | Proxied | Cloudflare CNAME flattening handles apex; Railway must also receive its TXT verification record |
| CNAME | `www` | `velkor.com.mx` | Proxied | Redirect or serve same app |
| TXT | `<RAILWAY_VERIFICATION_NAME>` | `<RAILWAY_VERIFICATION_VALUE>` | DNS only | Required by Railway custom-domain verification |
| CNAME | `api` | `<RAILWAY_API_CNAME_TARGET>` | Proxied | Optional; avoid unless Strapi admin/API must be public |
| TXT | `@` | `v=spf1 -all` | DNS only | Use while Velkor is receive-only; replace/merge with Resend-provided SPF when transactional sending is activated |
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:seguridad@velkor.com.mx; fo=1; adkim=s; aspf=s; pct=100` | DNS only | Start in monitor mode; move to quarantine/reject after reports |
| MX | `@` | `route1.mx.cloudflare.net` | DNS only | Added/managed by Cloudflare Email Routing |
| MX | `@` | `route2.mx.cloudflare.net` | DNS only | Added/managed by Cloudflare Email Routing |
| MX | `@` | `route3.mx.cloudflare.net` | DNS only | Added/managed by Cloudflare Email Routing |
| TXT | `cf2024-1._domainkey` | `<CLOUDFLARE_ROUTING_DKIM_VALUE>` | DNS only | Value provided by Cloudflare |

Cloudflare Email Routing assigns MX priorities automatically. Do not keep other MX records active while Email Routing is the inbound mail path. If Resend is used for `noreply@velkor.com.mx`, add the DKIM/SPF records generated by Resend before enforcing DMARC.

Recommended cache behavior:

| Rule | Expression | Action |
| --- | --- | --- |
| Bypass API | `http.request.uri.path starts_with "/api/"` | Bypass cache |
| Cache static Next assets | `http.request.uri.path starts_with "/_next/static/"` | Eligible for edge cache, respect origin headers |
| Cache public assets | `http.request.uri.path in {"/favicon.svg" "/favicon-white.svg" "/og-image.png" "/robots.txt" "/humans.txt"}` | Cache, respect origin headers |

Recommended WAF / rate rules:

| Rule | Expression | Action |
| --- | --- | --- |
| Assessment rate limit | `http.request.method eq "POST" and http.request.uri.path eq "/api/assessment"` | Managed Challenge above 8 requests / 60 seconds / IP |
| Contact/resource rate limit | `http.request.method eq "POST" and http.request.uri.path in {"/api/contacto" "/api/recurso-lead" "/api/assessment/notify"}` | Managed Challenge above 10 requests / 60 seconds / IP |
| Protect app API | `http.request.uri.path starts_with "/api/" and cf.threat_score gt 14` | Managed Challenge |
| Block obvious probes | `http.request.uri.path contains "/wp-" or http.request.uri.path contains ".env" or http.request.uri.path contains "/phpmyadmin"` | Block |
| High-risk traffic | `cf.threat_score gt 40` | Block |

- Confirm webhook receives `assessment.completed`.
- Confirm email delivery is either sent by Resend or logs `RESEND_API_KEY not configured`.
- Send test email to every alias and one unknown address for catch-all behavior.
- Confirm Cloudflare Security Events show no false-positive blocks for normal assessment submission.

## 8. Pending Risks

- Live Cloudflare mutation requires account access/API token or dashboard session.
- Railway custom-domain creation requires dashboard/API access; local CLI can read/set variables but returned `Unauthorized` for `railway domain`.
- Email Routing multi-recipient forwarding requires Email Worker, not only Custom Address rules.
- DMARC should remain monitor mode until Resend/domain sending authentication is confirmed, then move from `p=none` to `p=quarantine` and eventually `p=reject`.
- Bot Fight Mode can interfere with forms; enable only after assessment smoke test.
- Full (strict) conflicts with Railway's current proxied-domain guidance unless Railway has a custom certificate issued for the hostname; verify before enforcing.
- Root `railway.json` still appears older than app-level service configs; deploy from `apps/web` and `apps/api` service roots or fix Railway root-directory metadata.
